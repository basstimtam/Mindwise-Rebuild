# Mindwise Rebuild

人とCodexが、構想・設計・仕事・成果物を同じ地図から扱う、個人用の制作空間です。作業場所は `C:\Users\basst\Dropbox\AI Project\16.Mindwise-Rebuild`。契約は **Mindwise Rebuild Rev 2 / ACTIVE**、製品は初期実装中です。

## 起動と停止

このフォルダで `npm start` を実行し、表示された http://127.0.0.1:4316 を開きます。Node.js 24以降が必要です。現環境はv24.13.0で確認済み。追加パッケージの導入は不要です。停止は起動した画面で Ctrl+C。

1. 最初の枝を作るか、空の画面の「ゲームのサンプルで試す」を選びます。
2. 枝の内容・領域・具体化の深さ・状態・親・日程を編集します。表示の親と、仕様の依存関係は別です。
3. 共有する設定は「項目 = 値」で入力し、「仕様を適用する」で対象へつなぎます。局所設定を優先するときは、局所側から共有側へ理由付きの例外をつなぎます。異なる値が未解決の対象は制作を保留します。
4. 地図、階層、領域、プロセス、タスク、ガント、数値を切り替え、同じ枝を扱います。設定の変更前には判明した影響・例外・再確認対象を表示します。
5. 枝を選んで「Codexと制作」へ依頼します。有効設定と出所を渡し、開始時の対象と文脈に結び付けて実行します。
6. 制作後、結果が枝へ戻ります。「成果物と受入条件を確認」で現物を読み、条件を満たしていることを自分で確認して記録します。AIの終了だけでは確認済みにしません。
7. 必要な成果を指定して重みを入力すると、「領域別の進捗」で見積り済み範囲を集計します。同じ実ファイルの参照は全体で一度だけ数え、未定義/未見積りを残します。現物・条件・有効設定が変われば確認済みから外れます。
8. 「契約と判断の出所」で原文・版・状態・既存承認の記録へ戻れます。見出しを選び、選択中の枝へ出所を結ぶと、参照した版と指紋を保存します。「この対象の判断・変更を辿る」から、変更前後・判断理由・制作時の入力と原文を確認できます。
9. 「Codexに依頼すること」を「本文から設定案を作る」にすると、自由本文から選択対象の設定案を作ります。差分と影響を確認して採用し、その設定を次の制作に使えます。古い・未承認の出所では開始/採用/成果確認を止めます。
10. 数値は「入力値」「単位」「出所」「入力値の鮮度」を保存します。別の枝で入力値を空欄にし、式 `hours * rate` と参照名hours/rateに対象を選ぶと再計算します。例：3時間 × 1200円/時間 = 3600円。四則・括弧に対応し、単位は積/商/整数べき、無単位は `1`。欠損・循環・単位違い・古い入力は未解決です。式の結果から元の値・対象版・出所へ戻れます。数値や根拠の変更は関連成果の再確認へつながります。

数値の「現在として使用」は明示した入力の鮮度であり、現物受入や出所メモの文章との一致を証明しません。資料の自動取得・単位換算・厳密な十進会計は行いません。式は2000文字/512要素/括弧深さ32、参照50件/依存深さ256まで。範囲外の既存データは失わず、計算を未解決にします。

表示上の親の横にある「切り離す」で独立した枝にし、親の候補から付け替えられます。自分自身と子孫は親の候補に入りません。階層の枝はキーボードでも選択できます。枝の削除では子を独立して残し、「取り消す」で元の枝と関係を復元してその枝へ戻ります。未保存の入力は画面を開いている間、対象別に保持し、自分の切離し・削除/取消と矛盾しない入力を引き継ぎます。他の保存と同じ項目が変わった場合は競合として保持します。未保存入力をブラウザの再読込・停止から復元するものではありません。

成果物の確認は、直接関連付けた数値も確認範囲に含みます。数値との関係追加/解除は、保存前に成果の再確認先を示します。「関連する」で結んだだけでは手入力値自体を古くしません。入力の根拠や明示的な依存が変わった場合は、依存する入力値を再確認待ちにします。

保存済みの検証画面を再開する場合は、このフォルダのPowerShellで以下を実行します。

```powershell
$env:MINDWISE_DATA_DIR = Join-Path (Get-Location) '.runtime/spec-progress-workflow'
npm start
```

## 中断した制作の現物を照合する

「Codexと制作」にある「部分結果を照合」から、保存済み応答と専用フォルダの現物を照合します。揃った結果は差分と影響を見て地図への接続を回復できます。元の接続が受領済みなら枝へ再適用せず実行記録だけを回復し、取消や後続編集を保持します。欠落/改変/古い文脈/中断要求/回復情報不足は保留します。Codexの再制作・欠落ファイルの再作成・現物の上書きは行いません。

エラー応答は一部保存済みの可能性があるため、受領を再照合します。回復は成果物の受入確認とは別です。専用テキスト成果物の自動/故障試験と実APIを確認し、実画面でも欠落保留/現物本文と指紋/回復済み受領を確認しました。回復適用や記録だけの回復、回復応答失敗のUI操作は未確認です。試験モデルの二つの回復ケースは固定応答の架空データで、実Codex制作ではありません。

## 交換ファイルと判断の出所

「書き出す」は公開JSON形式2です。枝・関係に加え、全変更の差分/対象版/理由/入力/参照原文/取消状態と実行記録を保持します。「読み込む」でファイルを選ぶと、追加・削除・同IDの置換と変更前後を確認できます。確認した内容と保存版が一致するときだけ全置換し、元ファイルと現在の実行記録を閲覧専用の出所へ保管します。置換と保管は同じ保存処理で、途中失敗では両方を戻します。通常の「取り消す」で地図を戻せます。出所の保管は残ります。

取込元の「確認済み」は解除し、元の会話・操作受領・承認を現在の再開/採用/回復や権限には使いません。次の制作は新しい会話からです。対象の「判断・変更を辿る」または「保管した出所」で元案件・保存版・指紋と理由へ戻れます。個別の原記録も、その参照先とともに再書出できます。指紋は内容の一致であり、承認者の真正性を証明しません。

旧形式1は読み込めますが、元ファイルにない差分や理由を復元しません。未知版/未対応属性/重複ID/IDのない枝/指紋不一致/出所欠落は保存前に拒否し、原本を変えません。上限は6MiB・出所保管100件・一記録の変更詳細2万件。超過時は省略せず中止します。全データの保全にはSQLiteバックアップを使ってください。外部の成果物と認証情報は交換/バックアップのどちらにも含みません。マージやMindManager交換は未対応です。

交換の実画面試験は別保存先 `.runtime/exchange-workflow` / ポート4317で行いました。通常の版48の試験モデルを置換していません。保存後のHTTPエラーも同じ要求で受領を再確認し、二重に保存しないことを確認しました。
